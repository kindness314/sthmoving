# 阶段 5：离库流程云环境配置

成员提交离库申请、查看自己的申请状态、管理员审批/拒绝、管理员直接离库均通过 `api` 云函数完成。
申请记录、物品状态、物品版本、标签状态和操作日志必须在同一事务中保持一致。
管理员提醒仍属于阶段 6。

## 1. 部署

在项目根目录执行：

```powershell
npm run build:cloud
```

在微信开发者工具中上传并部署最新的 `cloudfunctions/api`，然后重新编译小程序。

## 2. 数据库集合与权限

确认存在 `outbound_requests` 集合，权限选择“所有用户不可读写”。小程序只能通过 `api` 云函数提交申请。

字段：

| 字段 | 说明 |
| --- | --- |
| `_id` | 申请 ID |
| `item_id` | 物品 ID |
| `applicant_id` | 申请人用户 ID |
| `reason` | 离库原因，同时作为操作日志提交梗概 |
| `status` | `PENDING` / `APPROVED` / `REJECTED` |
| `created_at`、`updated_at` | 创建和更新时间 |

## 3. 数据库索引

以下索引均为非唯一索引：

| 索引名称 | 索引字段顺序 | 字段升降序 | 唯一 | 用途 |
| --- | --- | --- | --- | --- |
| `outbound_item_status_created_at` | `item_id`、`status`、`created_at` | `item_id` 升序、`status` 升序、`created_at` 降序 | 否 | 检查同一物品是否存在待处理申请 |
| `outbound_applicant_created_at` | `applicant_id`、`created_at` | `applicant_id` 升序、`created_at` 降序 | 否 | 后续查询申请人的申请记录 |
| `outbound_status_created_at` | `status`、`created_at` | `status` 升序、`created_at` 降序 | 否 | 后续管理员按状态查看申请 |

云开发控制台不支持用普通唯一索引表达“每个物品最多一条 `PENDING` 申请”，该约束由云函数事务校验。

## 4. 人工验收

1. 使用已审核成员打开一个 `ACTIVE` 物品详情，确认显示“申请离库”按钮。
2. 填写 1–250 个字符的离库原因并提交，返回详情页后确认无需手动刷新就显示“离库申请中”；返回物品列表时状态也应同步更新。
3. 在 `outbound_requests` 中确认新增一条 `PENDING` 记录；在 `items` 中确认版本加一、状态为 `OUTBOUND_PENDING`；在 `item_operation_logs` 中确认新增 `OUTBOUND_REQUEST` 日志。
4. 再次提交同一物品的申请，应提示已有待处理申请，不能新增第二条申请。
5. 对已离库物品直接调用申请接口，应返回 `ITEM_NOT_REQUESTABLE`；普通成员不能调用管理员离库接口。
6. 原因为空或超过 250 个字符时，客户端和服务端都应拒绝。
