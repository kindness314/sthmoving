# 阶段 5 管理员离库处理云环境配置

本批次为阶段 5 的管理员操作：查看待处理申请、同意、拒绝、直接离库、批量离库、重新入库和已离库物品删除。
所有写操作均由云函数事务执行，客户端不能直接写 `items`、`outbound_requests`、
`item_labels` 或 `item_operation_logs`。

## 1. 部署

在项目根目录执行：

```powershell
npm run build:cloud
```

在微信开发者工具中上传并部署最新的 `cloudfunctions/api`，然后重新编译小程序。

## 2. 数据库集合与权限

确认以下集合均已创建，并设置为“所有用户不可读写”，仅允许 `api` 云函数事务访问：

- `items`
- `item_labels`
- `item_operation_logs`
- `outbound_requests`

`outbound_requests` 申请记录应包含：

| 字段 | 说明 |
| --- | --- |
| `_id` | 申请 ID |
| `item_id` | 物品 ID |
| `applicant_id` | 申请人用户 ID |
| `reason` | 成员离库原因 |
| `status` | `PENDING` / `APPROVED` / `REJECTED` |
| `reviewer_id` | 审核人用户 ID，同意或拒绝后写入 |
| `review_summary` | 拒绝时填写的审核原因，1～250 字；同意时不写入 |
| `reviewed_at` | 审核时间 |
| `created_at`、`updated_at` | 创建和更新时间 |

## 3. 索引

以下索引均为非唯一索引，创建时不要省略索引名称、字段顺序和升降序：

| 索引名称 | 索引字段顺序 | 字段升降序 | 唯一 | 用途 |
| --- | --- | --- | --- | --- |
| `outbound_item_status_created_at` | `item_id`、`status`、`created_at` | `item_id` 升序、`status` 升序、`created_at` 降序 | 否 | 检查物品待处理申请 |
| `outbound_applicant_created_at` | `applicant_id`、`created_at` | `applicant_id` 升序、`created_at` 降序 | 否 | 查询申请人申请 |
| `outbound_status_created_at` | `status`、`created_at` | `status` 升序、`created_at` 降序 | 否 | 管理员按状态列出申请 |

## 4. 管理员操作规则

1. `ADMIN` 和 `OWNER` 才能调用 `listPending`、`approve`、`reject`、`direct`、`batchDirect`、`restore`、`batchRestore`、`batchDelete`；服务端不信任客户端角色。
2. 同意申请时无需填写梗概，事务必须同时完成：申请改为 `APPROVED`、物品改为 `OFF_SHELF`、物品版本加一、写入审核人/时间、写入 `OUTBOUND_APPROVE` 日志、标签改为 `VOID`。
3. 拒绝申请时，事务必须同时完成：申请改为 `REJECTED`、物品从 `OUTBOUND_PENDING` 恢复为 `ACTIVE`、物品版本加一、写入审核人/梗概/时间和 `OUTBOUND_REJECT` 日志；标签保持原状态。
4. 直接离库要求提交梗概和当前物品版本；事务写入 `OUTBOUND` 日志并将标签改为 `VOID`。
5. 批量离库最多处理 50 件 `ACTIVE` 物品；每件物品都提交 `item_id` 和 `expected_version`，任一版本冲突时整批回滚。
6. 已处理的申请、已离库物品和版本不一致的请求必须返回明确错误，不得覆盖最新状态。
7. 管理员/所有者可以批量删除 `OFF_SHELF` 物品；删除物品记录和物品图片，但保留操作日志、离库申请和 `VOID` 标签。
8. 管理员/所有者可以调用 `restore` 或 `batchRestore` 将一件或多件 `OFF_SHELF` 物品恢复为 `ACTIVE`；批量操作填写一次提交梗概，恢复前业务字段不变、每件物品版本加一、标签从 `VOID` 恢复为离库前状态，并为每件物品写入 `INBOUND` 日志。批量任一版本或标签状态冲突时整批回滚。删除后的旧标签不可复用，扫码显示物品已删除或标签已失效。
9. 数据删除事务成功后再清理图片文件；若云存储清理失败，接口返回 `ITEM_IMAGE_DELETE_FAILED` 及待处理物品 ID，不伪装为完全成功。

## 5. 小程序入口

- 管理员/所有者首页显示“离库审核”，进入待处理申请列表；
- 申请卡片显示物品名称、编码、申请人、原因和申请时间；
- 拒绝前必须填写 1～250 字拒绝原因；同意前只需二次确认；
- 管理员/所有者在 ACTIVE 物品详情页可选择“直接离库”，必须填写操作梗概；
- 管理员/所有者在普通物品查询页进入“批量离库”，只能选择 `ACTIVE` 物品；
- 管理员/所有者从首页进入“离库物品管理”，这里只显示 `OFF_SHELF` 物品并提供单件/批量重新入库和删除入口；
- 成员仍只能看到“申请离库”，不能看到或调用管理员操作。

## 6. 人工验收

1. 用管理员账号打开首页，确认出现“离库审核”；用普通成员账号确认不出现该入口。
2. 成员提交申请后，管理员进入列表，确认能看到物品名称、编码、申请人和原因。
3. 管理员同意申请，确认物品变为 `OFF_SHELF`、版本加一、申请变为 `APPROVED`、标签变为 `VOID`，并新增 `OUTBOUND_APPROVE` 日志。
4. 重新准备一个在库物品，管理员拒绝申请，确认物品恢复 `ACTIVE`、版本加一、申请变为 `REJECTED`，并新增 `OUTBOUND_REJECT` 日志；成员随后可再次申请。
5. 管理员在 ACTIVE 物品详情页直接离库，确认新增 `OUTBOUND` 日志并作废标签；管理员在离库物品管理页可看到重新入库入口。
6. 管理员在物品列表进入批量管理，选择两件 ACTIVE 物品并批量离库，确认每件物品都变为 `OFF_SHELF`、标签为 `VOID`、各新增一条 `OUTBOUND` 日志。
7. 管理员在离库物品管理页选择一件物品重新入库，确认状态变为 `ACTIVE`、版本加一、标签恢复为 `READY`、新增 `INBOUND` 日志，名称/详情/图片/数量/分类保持不变；再选择两件物品批量重新入库，确认每件物品都完成同样的恢复。
8. 管理员从首页进入离库物品管理，确认列表只包含已离库物品；选择一件物品即可完成单件删除，选择多件物品可批量删除，确认物品记录和图片删除，操作日志、离库申请和 `VOID` 标签仍存在。
9. 两名管理员同时处理同一申请，只有一个请求成功，另一个返回已处理或状态冲突；版本不一致的批量离库或批量重新入库返回 `VERSION_CONFLICT` 且不覆盖最新状态。
10. 普通成员通过开发者工具调用管理员动作，服务端返回 `FORBIDDEN`。
