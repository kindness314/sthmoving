# 迁移准备云环境配置

本文用于部署物品与分类的软删除改造。改造后删除操作不再移除文档，而是把 `status`
标记为 `DELETED`，并记录 `deleted_by` 与 `deleted_at`。

## 1. 状态取值变化

`items.status` 增加 `DELETED`，取值为 `ACTIVE`、`OUTBOUND_PENDING`、`OFF_SHELF`、
`DELETED`。`categories.status` 增加 `DELETED`，取值为 `ACTIVE`、`DISABLED`、
`DELETED`。

服务端在按 ID 读取物品和分类时排除 `DELETED`，物品查询接口的状态筛选只接受前三个
取值，因此已删除记录不会出现在任何列表或详情中。

`item_labels`、`item_operation_logs` 和 `outbound_requests` 保持原有行为，删除物品
时仍保留这些记录，标签仍标记为 `VOID`。

## 2. 预设分类字段变化

预设分类不再写入 `created_by`。历史数据中该字段值为 `SYSTEM` 的九条预设分类可以保留，
也可以在控制台清除该字段，两者都不影响接口行为。

## 3. 调整索引

分类删除前的引用检查改为按 `category_id` 与 `status` 联合查询，需要在 `items` 的
“索引管理”中创建：

| 索引名称 | 索引字段 | 唯一 |
| --- | --- | --- |
| `category_id_status` | `category_id` 升序、`status` 升序 | 否 |

原有的 `category_id` 单字段索引可以保留。`items` 与 `categories` 的其余索引不变。

## 4. 部署云函数

在项目根目录执行：

```powershell
npm run build:cloud
```

然后在微信开发者工具中右键 `cloudfunctions/api`，选择
“上传并部署：云端安装依赖”。

## 5. 人工验收

1. 使用管理员账号在“离库物品管理”中删除一件已离库物品，列表应不再显示该物品。
2. 在云开发控制台查看 `items`，该文档仍然存在，`status` 为 `DELETED`，且带有
   `deleted_by` 与 `deleted_at`。
3. 该物品的操作日志、离库申请仍在，标签状态为 `VOID`。
4. 扫描该物品已打印的标签，应提示物品已删除。
5. 在“我的申请”中查看该物品的历史申请，应显示为已删除。
6. 新建一个自定义分类并用于登记物品，此时删除该分类应提示只能停用。
7. 删除该物品后再删除该分类，应删除成功且分类管理页不再显示。
8. 再次新建同名分类，应创建成功。
