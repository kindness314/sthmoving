# 自建后端部署

面向一台普通云服务器（2 核 4 GB / 50 GB，Ubuntu 24.04），用 Docker Compose 跑
PostgreSQL、Node API 和 Caddy 三个服务。只有 Caddy 对外暴露 80 与 443 端口。

## 1. 准备

服务器安装 Docker Engine 与 Compose 插件，把域名 A 记录指向服务器公网 IP。
Caddy 会用 Let's Encrypt 自动签发并续期证书，不需要手工准备证书文件。

克隆仓库后在仓库根目录创建 `.env`：

```
SITE_ADDRESS=sthmoving.example.com
PUBLIC_BASE_URL=https://sthmoving.example.com
POSTGRES_PASSWORD=<随机口令>
WECHAT_APP_ID=<小程序 AppID>
WECHAT_APP_SECRET=<小程序密钥>
FILE_SIGNING_SECRET=<至少 32 位随机串>
MINI_PROGRAM_ENVIRONMENT=release
OWNER_BOOTSTRAP_TOKEN=<至少 16 位随机串，初始化完成后删掉>
```

口令用 `openssl rand -hex 32` 生成。`.env` 不进仓库，权限设为 600。

`PUBLIC_BASE_URL` 决定所有图片签名地址的域名，填错会让全部图片打不开。

## 2. 启动

```
docker compose up -d --build
docker compose ps
curl https://sthmoving.example.com/health
```

`/health` 返回 `{"ok":true,"data":{"status":"ok"}}` 表示数据库已连通。API 启动时会
自动执行 `server/migrations` 下尚未应用的迁移。

## 3. 微信后台配置

1. **服务器域名**：开发管理 → 开发设置 → 服务器域名，把 `https://sthmoving.example.com`
   加入 request 与 downloadFile 合法域名。
2. **IP 白名单**：开发管理 → 开发设置 → IP 白名单，加入服务器的**出口** IP。
   在服务器上执行 `curl https://ifconfig.me` 拿到该地址。不加白名单时
   `code2Session` 与小程序码生成都会失败，这一步只能在拿到服务器之后验证。
3. 小程序端把 `miniprogram/config/env.ts` 的 `apiBaseUrl` 改成同一个域名后重新上传。

## 4. 初始化首位所有者

数据是全新的时候，用小程序登录后调用一次 `auth.bootstrapOwner`，口令取 `.env` 里的
`OWNER_BOOTSTRAP_TOKEN`。成功后从 `.env` 删除该变量并 `docker compose up -d` 使其生效，
之后任何人再调用都会得到 `OWNER_BOOTSTRAP_CLOSED`。

从云开发迁移数据的场景不需要这一步，所有者随数据一起导入。

## 5. 备份

```
DATABASE_URL=postgres://sthmoving:<口令>@127.0.0.1:5432/sthmoving \
STORAGE_ROOT=/var/lib/docker/volumes/sthmoving_api-files/_data \
  ./scripts/backup.sh /srv/backups
```

数据库未对外暴露端口，从宿主机执行时用
`docker compose exec -T postgres pg_dump` 更方便；恢复见 `scripts/restore.sh`。
建议加一条每日 cron，并把备份同步到服务器之外。

## 6. 排查

| 现象 | 原因 |
|---|---|
| `/health` 返回 503 | API 连不上数据库，看 `docker compose logs postgres` |
| 登录返回 `SERVICE_UNAVAILABLE` | 多半是 IP 白名单没加，或 AppSecret 填错 |
| 图片打不开 | `PUBLIC_BASE_URL` 与实际域名不一致，或签名已过期（默认 10 分钟） |
| 生成小程序码报凭证失效 | 白名单未生效；服务端已自动重试一次，仍失败说明配置问题 |
| 上传返回 413 | 图片超过 5 MB，或 Caddy 的 `max_size` 被改小 |
