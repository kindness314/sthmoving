# 审核测试环境（沙箱）

> 目的：微信审核要求提供可体验全部功能的测试账号，而本小程序是微信一键登录 + 管理员审批制，
> 审核员用自己的微信进来只会停在「加入审核」页。本方案在生产服务端内置一个**与生产物理隔离**的
> 沙箱数据域，审核员凭一次性口令从登录页进入，自动成为沙箱所有者，可体验全部功能。

## 1. 设计要点

| 维度 | 生产域（prod） | 沙箱域（test） |
| --- | --- | --- |
| 数据库 | `DATABASE_URL` | `TEST_DATABASE_URL`（独立库，同源迁移） |
| 文件存储 | `STORAGE_ROOT` | `TEST_STORAGE_ROOT`（独立目录） |
| 文件签名密钥 | `FILE_SIGNING_SECRET` | `TEST_FILE_SIGNING_SECRET`（不同密钥，签名不可跨域） |
| 会话令牌 | 随机串 | 前缀 `t1_` + 随机串 |
| 身份 | 微信 openid | 固定沙箱身份 `review:sandbox`（id `e6ea63d048b2babb58458f35aae1afb6`） |

- 会话令牌是**不透明随机串、按库存储**，因此跨库天然不通用；鉴权器按 `t1_` 前缀判定数据域，
  路由再按数据域分发到对应的一套仓储/存储/会话。
- 沙箱库与生产库用**同一套迁移**，启动时自动建表，schema 永不漂移。
- 沙箱身份首次登录时预置，角色 `OWNER`、状态 `APPROVED`，因此审核员能看到并操作全部功能。

## 2. 控制面（开关与口令）

- 位置：成员管理页「测试账号」卡片，**仅实际管理者（MANAGER）与所有者（OWNER）**可见可操作。
- 口令：16 位高随机字符（30 字符表，去掉易混的 I/L/O/U/0/1），只在生成时返回一次并四位分组展示；
  服务端只存 `sha256(salt + ":" + 规范化口令)`，不保存明文。
- 生命周期：**有效期内可重复使用**（默认 7 天，`TEST_ACCESS_TTL_HOURS`）；
  「重新生成」立即作废旧口令；「关闭测试入口」立即作废口令**并吊销沙箱全部会话**。
- 限流：`/auth/test-session` 每 IP 每分钟 5 次；`/auth/test-access` 每 IP 每分钟 30 次。

## 3. 可见性约束（重要）

- 登录页的圆形测试入口**只在开关开启时**渲染，平时完全不可见（状态查询失败一律视为关闭）。
- 测试账号卡片只在**生产域**且身份为实际管理者/所有者时才请求与渲染。
- **沙箱域内不提供**测试入口管理（`review.*` 返回 `TEST_ACCESS_UNAVAILABLE`），审核员看不到测试后台。

## 4. 环境变量

在服务器 `.env` 增加（未配置 `TEST_DATABASE_URL` 时沙箱整体关闭，行为与从前完全一致）：

```
TEST_DATABASE_URL=postgres://sthmoving:<口令>@postgres:5432/sthmoving_sandbox
TEST_ACCESS_TTL_HOURS=168
# 以下两项可不填，缺省时：STORAGE_ROOT 下 __test 子目录 + 由生产密钥派生
# TEST_STORAGE_ROOT=/var/lib/sthmoving/files
# TEST_FILE_SIGNING_SECRET=<至少 32 位随机串>
```

## 5. 运维步骤

### 5.1 首次准备（一次性；**生产环境已完成**）

```bash
ssh -i ~/.ssh/sthmoving_deploy ubuntu@<服务器>
cd ~/sthmoving

# 1) 建沙箱库（与生产同实例、不同 database，物理隔离）
docker compose exec -T postgres \
  psql -U sthmoving -d sthmoving -c 'CREATE DATABASE sthmoving_sandbox'

# 2) 写入 .env 的 TEST_DATABASE_URL（见第 4 节），然后重启 api
#    启动时会自动对沙箱库执行 server/migrations 全量迁移
docker compose up -d api
docker compose ps
curl https://<域名>/health
```

### 5.2 每次审核

1. 小程序 → 成员管理 → 测试账号 → **生成测试口令**（复制口令，形如 `XXXX-XXXX-XXXX-XXXX`）。
2. 微信后台提交审核时填写：
   - 测试账号：`点击登录页右下角圆形按钮，输入下方口令` + 口令原文
   - 或按下方备注说明
3. 审核结束后点 **关闭测试入口**（口令作废、沙箱会话全部吊销）。

审核备注参考文案：

> 本小程序为组织内部物品管理工具，采用微信一键登录，无独立账号密码。测试账号信息：
> 打开小程序 → 点击登录页右下角圆形按钮 → 输入口令 `XXXX-XXXX-XXXX-XXXX` → 即进入独立的
> 测试数据环境（管理员权限，可完整体验物品登记、搜索、扫码查询、离库申请与审批、蓝牙标签打印）。
> 该环境与正式数据完全隔离。

## 6. 安全边界与验收

- [ ] 沙箱库与生产库是不同 database，互不可见（`listMembers` 两边结果不交叉）
- [ ] 沙箱令牌不能访问生产数据；生产令牌在沙箱域被拒
- [ ] 沙箱内 `review.*` 返回 `TEST_ACCESS_UNAVAILABLE`
- [ ] 口令错误/未开启/已关闭分别返回 `INVALID_TEST_PASSWORD` / `TEST_ACCESS_CLOSED`
- [ ] 关闭入口后沙箱会话立即失效（`UNAUTHENTICATED`）
- [ ] 登录页平时看不到测试入口

**可用性保证**：沙箱是可选功能。它的库不可达或迁移失败时，服务会记录错误并**降级为「入口关闭」**，
生产服务照常启动与运行（覆盖见 `tests/server/review.postgres.test.ts` 的降级用例）；
同理，沙箱被降级时服务端也不再接受任何 `t1_` 前缀的令牌。

自动化覆盖：`tests/server/review.test.ts`（单元）与 `tests/server/review.postgres.test.ts`（真库 + 真 HTTP 的端到端）。

## 7. 演示数据

沙箱预置了一份演示数据，审核员打开即可试功能；每次审核前都可用脚本重置到这份状态：

- 4 个业务分类（活动器材 / 办公用品 / 舞台设备 / 宣传物料），另有系统内置默认分类
- 9 件物品：7 件在库（其中 5 件带图片）、1 件有待审批的离库申请、1 件已离库
- 1 条待审批的成员加入申请（申请人「小林」）
- 操作日志由接口自动生成，不需要手工造

### 重置与填充

```bash
# 1) 清空沙箱（只动 sthmoving_sandbox，生产库不受影响）
docker compose exec -T postgres psql -U sthmoving -d sthmoving_sandbox -c \
  "TRUNCATE users, join_requests, sessions, files, item_operation_logs, item_labels, outbound_requests, categories, items, test_access RESTART IDENTITY CASCADE"
docker compose exec -T api sh -c 'rm -rf /var/lib/sthmoving/files/__test/*'

# 2) 成员管理页生成测试口令，然后用脚本填充（脚本无依赖，不需要 npm install）
docker run --rm --network sthmoving_default -v "$PWD":/app -w /app node:24-alpine \
  node scripts/seed-sandbox-demo.mjs --base https://<域名> --password <测试口令>

# 3) 追加待审批的成员申请（没有第二个微信号可登录，故用 SQL 造）
docker compose exec -T postgres psql -U sthmoving -d sthmoving_sandbox -c \
  "INSERT INTO users (id, openid, display_name, role, status, created_at, updated_at) VALUES ('2ff4083e0fc0df01e8a426fd40376a80', 'review:applicant', '小林', 'MEMBER', 'PENDING', now(), now()); INSERT INTO join_requests (id, applicant_id, display_name, requested_role, status, created_at, updated_at) VALUES (gen_random_uuid()::text, '2ff4083e0fc0df01e8a426fd40376a80', '小林', 'ADMIN', 'PENDING', now(), now());"
```

`2ff4083e0fc0df01e8a426fd40376a80` 是 `sha256('review:applicant')` 的前 32 位，与沙箱身份命名规则一致。

## 8. 已知限制

- 沙箱与生产共用 AppID 与微信接口配置，因此沙箱内生成的小程序码仍指向正式环境；
  审核演示请以界面操作为准，不必扫码。
- 小程序码/订阅消息等对外副作用在沙箱内同样会消耗额度。
- `OWNER_BOOTSTRAP_TOKEN` 是全进程单值，沙箱域同样可用（仅重建初始所有者时需要，平时不设）。
