# 阶段 2 物品登记后端云环境配置

本文用于部署物品登记、初始版本和首条操作日志功能。本批次不包含登记页面与图片上传界面。

## 1. 创建数据库集合

在微信开发者工具的云开发控制台中确认或创建：

- `items`
- `item_operation_logs`

两个集合的权限类型均选择“所有用户不可读写”。小程序客户端只能通过 `api` 云函数登记物品，不能直接写数据库。

## 2. 创建索引

在 `items` 的“索引管理”中确认或创建：

| 索引名称 | 索引字段 | 唯一 |
| --- | --- | --- |
| `code` | `code` 升序 | 是 |
| `category_id` | `category_id` 升序 | 否 |

`code` 是服务端生成的随机公开编码，客户端不能指定。唯一索引用于保证实体标签编码不会重复。

在 `item_operation_logs` 的“索引管理”中创建：

| 索引名称 | 索引字段 | 唯一 |
| --- | --- | --- |
| `item_created_at` | `item_id` 升序、`created_at` 降序 | 否 |

## 3. 部署云函数

在项目根目录执行：

```powershell
npm run build:cloud
```

然后在微信开发者工具中右键 `cloudfunctions/api`，选择“上传并部署：云端安装依赖”。

## 4. 控制台验收

先在 `categories` 集合复制一个状态为 `ACTIVE` 的分类 `_id`，替换下方的 `categoryId`：

```javascript
wx.cloud.callFunction({
  name: 'api',
  data: {
    module: 'items',
    action: 'create',
    payload: {
      name: '折叠桌',
      images: [],
      description: '活动使用',
      quantityMode: 'SINGLE',
      quantity: 1,
      categoryId: '替换为启用分类的_id',
      commitSummary: '首次登记物品'
    }
  }
}).then(({ result }) => console.log(result))
```

预期返回 `ok: true`，并满足：

1. `items` 新增一条记录，`status` 为 `ACTIVE`、`version` 为 `1`。
2. `quantity_mode` 为 `SINGLE`、`quantity` 为 `1`。
3. `registered_by` 和 `updated_by` 是当前已审核成员的用户 ID。
4. `code` 是服务端生成的 12 位大写十六进制编码。
5. `item_operation_logs` 同时新增一条 `CREATE` 日志。
6. 日志的 `version_before` 为 `0`、`version_after` 为 `1`，提交梗概为“首次登记物品”。
7. 对应分类的 `item_reference_count` 增加 `1`；该计数只增不减，用于阻止删除曾被物品引用的分类。

再分别验证：

- 将 `SINGLE` 的 `quantity` 改为 `2`，应返回 `INVALID_ITEM_QUANTITY`。
- 将 `quantityMode` 改为 `MULTIPLE` 且 `quantity` 改为正整数，应登记成功。
- 使用已停用分类，应返回 `CATEGORY_DISABLED`。
- 使用未审核账号，应返回 `ACCOUNT_NOT_ACTIVE`。

分类引用计数、物品与首条日志在同一数据库事务中写入，任一步失败都不能留下半条登记数据。
