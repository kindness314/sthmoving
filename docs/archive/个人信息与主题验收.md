# 个人信息与主题验收

## 1. 部署前检查

在仓库根目录执行：

```powershell
npm run check
npm run build:cloud
```

随后在微信开发者工具中上传并部署 `cloudfunctions/api`，选择“云端安装依赖”，再重新编译小程序。

本功能沿用 `users` 集合和现有云存储，不需要新建集合或索引。新增字段会在用户保存资料或首次通过审核时写入：

- `gender`
- `theme`
- `joined_at`
- `avatar_url`（用户设置头像后写入）

## 2. 基础资料验收

1. 使用已通过审核的账号进入工作台。
2. 确认页面右上角显示紧凑的“工作台”和“个人资料”切换，两个入口可以互相切换且不会悬浮遮挡内容。
3. 进入个人信息页，确认昵称、身份、状态和加入时间正确。
4. 将昵称改为 1 个字符并保存，应成功；输入空白昵称或超过 40 个字符，应在客户端或服务端被拒绝。
5. 将性别依次改为“未知”“女”“男”，保存并重新进入页面，确认结果保持。

## 3. 头像验收

1. 未设置头像时，应显示稳定的纯色圆形头像和昵称首字；重新进入后颜色不应随机变化。
2. 点击头像，从相册和相机各选择一次图片，确认上传后立即显示新头像。
3. 上传超过 5 MB 的图片应被拒绝，原头像保持不变。
4. 关闭并重新进入小程序，确认头像仍能正常加载。

## 4. 主题验收

1. 依次选择藏青、靛蓝、湛蓝、深青、松绿、橄榄、赭橙、朱砂、绛红、茄紫、雾灰和咖褐并保存。
2. 每次保存后检查个人信息页、底栏、工作台、物品查询、物品详情、分类管理和审核页面的主按钮、标签、图标底色及顶栏。
3. 关闭并重新进入小程序，确认最后保存的主题保持不变。
4. 检查白色按钮文字、正文和弱化文字均清晰可读，没有颜色相近导致的辨识问题。

## 5. 权限与兼容验收

1. 未申请、待审核、被拒绝和已停用账号不得进入个人信息页保存资料。
2. 分别使用普通成员、管理员、实际管理者和所有者账号检查身份名称。
3. 新批准账号的加入时间应等于审核通过时间，并且后续角色调整不改变加入时间。
4. 对升级前已经通过审核、尚无 `joined_at` 的账号，页面使用已有审核时间作为兼容显示；该账号下次资料保存不会改变此显示值。

## 6. 通过标准

- 昵称、性别、头像和主题保存后重新进入仍保持；
- 服务端拒绝未审核账号和非法字段；
- 头像失败流程不覆盖原头像；
- 四种角色信息显示正确；
- 十二套主题在所有核心页面没有明显错色、文字不可读或顶栏不一致；
- Android 和 iOS 各完成至少一次头像与主题真机验收。
