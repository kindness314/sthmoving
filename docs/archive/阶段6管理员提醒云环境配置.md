# 阶段 6 管理员提醒云环境配置

> 历史文档：当前产品不再新增 `notifications` 待办写入，也不设置独立通知页。成员申请和离库申请的待处理数量直接由对应审核模块查询；本文件仅用于历史数据迁移参考，不作为当前验收步骤。

本阶段先交付小程序内管理员提醒：成员加入申请和物品离库申请会为每位有效管理员创建独立提醒，管理员可以查看未读数、查看申请最终状态并标记已读。
微信订阅消息需要在公众平台取得模板 ID 后再接入，不影响站内提醒使用。

## 1. 创建集合与权限

在云开发控制台创建 `notifications` 集合，权限设置为“所有用户不可读写”，仅允许 `api` 云函数访问。

字段如下：

| 字段 | 说明 |
| --- | --- |
| `_id` | 提醒 ID，由云函数按申请和接收人生成 |
| `recipient_id` | 接收提醒的管理员或所有者用户 ID |
| `kind` | `JOIN_REQUEST` 或 `OUTBOUND_REQUEST` |
| `title` | 提醒标题 |
| `body` | 提醒摘要 |
| `target` | `MEMBER_REVIEW` 或 `OUTBOUND_REVIEW` |
| `target_id` | 对应的加入申请或离库申请 ID |
| `status` | `UNREAD` 或 `READ` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `read_at` | 标记已读时间，可为空 |

## 2. 创建索引

创建以下非唯一索引，不要省略索引名称、字段顺序和升降序：

| 索引名称 | 索引字段顺序 | 字段升降序 | 唯一 | 用途 |
| --- | --- | --- | --- | --- |
| `notification_recipient_status_created_at` | `recipient_id`、`status`、`created_at` | `recipient_id` 升序、`status` 升序、`created_at` 降序 | 否 | 管理员未读数和提醒列表 |

## 3. 部署

在项目根目录执行：

```powershell
npm run build:cloud
```

在微信开发者工具中上传并部署最新的 `cloudfunctions/api`，重新编译小程序。

## 4. 人工验收

1. 使用管理员或所有者账号打开工作台，确认“仓库管理”区域出现“管理员提醒”。
2. 使用另一个账号提交加入组织申请，所有有效管理员的提醒列表均出现“新的成员加入申请”。
3. 使用成员提交离库申请，所有有效管理员的提醒列表均出现“新的离库申请”。
4. 首页入口显示未读数量；进入提醒列表后，未读提醒有明显样式区分。
5. 点击待处理提醒后标记为已读，并进入对应的成员审核或离库审核页面。
6. 一名管理员先处理申请，另一名管理员打开自己的提醒列表时，应看到申请的最终状态（已通过或已拒绝）。
7. 普通成员调用 `notifications.list` 或 `notifications.markRead` 时，服务端返回 `FORBIDDEN`。
8. 不同管理员的已读状态相互独立；一名管理员标记已读不能清除另一名管理员的未读提醒。
