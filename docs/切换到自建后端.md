# 切换到自建后端

把线上流量从微信云开发切到自建后端。整个过程需要一个维护窗口，期间成员不能登记或修改
物品。建议选在使用低谷，预留 2 小时，其中实际操作约 30 分钟，其余留给验收和回滚余量。

## 切换前必须已完成

- [ ] 服务器按 [自建后端部署](./自建后端部署.md) 跑通，`/health` 返回正常
- [ ] 微信后台已加合法域名，**IP 白名单已加服务器出口 IP 并实测过登录**
- [ ] 小程序 `apiBaseUrl` 已改为正式域名，新版本已提交审核并通过，但**尚未发布**
- [ ] 用一份生产数据的副本完整演练过一次导入，`npm run migrate -- check` 零问题
- [ ] 云开发环境已做一次完整备份

AppID 必须与迁移前一致。用户标识是 `openid` 的摘要，换 AppID 会让全部数据成为孤儿，
导入前的 `check` 会直接报出来。

## 时间线

**T-0 停写。** 在云开发控制台把 `api` 云函数替换成只返回固定错误的版本，让所有旧客户端
立刻停止写入：

```js
exports.main = async () => ({
  ok: false,
  error: { code: 'SERVICE_MOVED', message: '服务已升级，请重启小程序' },
})
```

这一步是整个切换的关键。跳过它，在导出之后仍会有数据写进云数据库，那部分数据会永久丢失。

**T+5 导出。** 在云开发控制台把 7 个集合导出为 JSON Lines，下载云存储全部文件。

**T+15 导入。** 按 [README 的迁移步骤](../README.md#从微信云开发迁移数据) 依次执行
`check`、`plan-files`、搬迁文件、`import`。`import` 会在文件缺失或数量对不上时终止。

**T+25 发布小程序。** 在微信后台把已审核通过的版本设为线上版本。

**T+30 验收。** 用两个账号（一个管理员、一个普通成员）走一遍：

- [ ] 登录后角色、状态与切换前一致
- [ ] 物品列表数量与导出数量一致，搜索和分类筛选正常
- [ ] 物品详情的图片能正常显示（说明 `files` 表和签名地址都对）
- [ ] 扫一个已有实体标签，能跳进对应物品详情
- [ ] 新登记一件带图片的物品，生成小程序码并预览
- [ ] 提交一条离库申请并由管理员审批

## 回滚

**发布小程序之前**回滚：把云函数恢复成原来的版本即可，自建后端的数据丢弃，成员无感知。

**发布小程序之后**回滚：需要把小程序版本回退到上一版并恢复云函数，同时把切换后写入
自建后端的数据手工补回云开发。这一步没有自动化工具，所以验收不通过时优先在自建后端上
修复，而不是回滚。因此上面的"必须已完成"清单里，演练那一条不能省。

## 观察期

原云开发环境**保留至少 30 天**，不要立刻删除数据。观察期内每天确认：

- `docker compose ps` 三个服务都是 healthy
- `docker compose logs api | grep -i error` 无反复出现的错误
- 备份任务有产出，且随机抽一份验证过 `restore.sh` 能恢复

30 天后确认无异常，再清理云开发环境，并从 `.env` 删除 `OWNER_BOOTSTRAP_TOKEN`
（如果还没删）。
